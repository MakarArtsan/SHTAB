## 2026-08-30 · Этап 0 · Каркас монорепозитория

**Сделано.**

- Структура `/api /web /infra /docs /data`, документы проекта в `/docs`.
- `infra/docker-compose.yml` — локальный запуск: свой образ PostgreSQL 16
  (PostGIS + доставленный pgvector, плюс ltree и pg_trgm через init-скрипт),
  Redis, MinIO с автосозданием бакета, api и web с горячей перезагрузкой.
  Обратного прокси локально нет — api и web открыты напрямую.
- `infra/docker-compose.prod.yml` и `infra/Caddyfile` — заготовка деплоя:
  Caddy сам берёт сертификат, раздаёт собранную статику, проксирует
  `/api`, `/ws` и `/health`; медиа — на поддомене `s3.{DOMAIN}`,
  чтобы presigned-ссылки не ломались подменой пути.
- `Makefile`: `up down logs migrate revision seed test lint`. Цель `.env`
  создаёт файл из `.env.example` сама, так что `make up` работает после клона.
- API: `GET /health`, единый формат ошибок `{"error": {...}}` с русскими
  текстами, настройки через `pydantic-settings`, Alembic настроен
  (ревизий пока нет, `upgrade head` проходит вхолостую).
- `make seed` пока не заливает данные — модели ещё нет. Вместо этого проверяет,
  что все четыре расширения PostgreSQL действительно включены, и падает, если нет.
- web: React 18 + TS strict + Vite + Tailwind, база shadcn/ui (`components.json`,
  CSS-переменные, `cn`). Заглушка показывает название и статус связи с API.
- `data/categories.json` — категории инцидентов, приоритеты и целевое время реакции.

**Чем проверено.**

- `ruff check .` — чисто; `mypy app` (strict) — 11 файлов без ошибок; `pytest` — 2 теста.
- Живой `uvicorn`: `GET /health` → 200 `{"status":"ok",...}`,
  несуществующий путь → 404 в едином формате.
- `alembic upgrade head --sql` — env.py и alembic.ini разбираются, offline-режим проходит.
- `eslint` + `tsc --noEmit` (два проекта) — чисто; `vitest` — 1 тест; `vite build` — сборка проходит.
- `docker compose config` — оба compose-файла валидны.
