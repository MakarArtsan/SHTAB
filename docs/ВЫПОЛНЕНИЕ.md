## 2026-08-30 · Этап 0 · Каркас монорепозитория

**Сделано.**

- Структура `/api /web /infra /docs /data`, документы проекта в `/docs`.
- `infra/docker-compose.yml` — локальный запуск: свой образ PostgreSQL 16
  (PostGIS + доставленный pgvector, плюс ltree и pg_trgm через init-скрипт),
  Redis, MinIO с автосозданием бакета, api и web с горячей перезагрузкой.
  Обратного прокси локально нет — api и web открыты напрямую.
- `infra/docker-compose.prod.yml` и `infra/Caddyfile` — заготовка деплоя:
  Caddy сам берёт сертификат, раздаёт собранную статику, проксирует
  `/api`, `/ws` и `/health`; медиа — на поддомене `s3.{DOMAIN}`,
  чтобы presigned-ссылки не ломались подменой пути.
- `Makefile`: `up down logs migrate revision seed test lint`. Цель `.env`
  создаёт файл из `.env.example` сама, так что `make up` работает после клона.
- API: `GET /health`, единый формат ошибок `{"error": {...}}` с русскими
  текстами, настройки через `pydantic-settings`, Alembic настроен
  (ревизий пока нет, `upgrade head` проходит вхолостую).
- `make seed` пока не заливает данные — модели ещё нет. Вместо этого проверяет,
  что все четыре расширения PostgreSQL действительно включены, и падает, если нет.
- web: React 18 + TS strict + Vite + Tailwind, база shadcn/ui (`components.json`,
  CSS-переменные, `cn`). Заглушка показывает название и статус связи с API.
- `data/categories.json` — категории инцидентов, приоритеты и целевое время реакции.

**Чем проверено.**

- `ruff check .` — чисто; `mypy app` (strict) — 11 файлов без ошибок; `pytest` — 2 теста.
- Живой `uvicorn`: `GET /health` → 200 `{"status":"ok",...}`,
  несуществующий путь → 404 в едином формате.
- `alembic upgrade head --sql` — env.py и alembic.ini разбираются, offline-режим проходит.
- `eslint` + `tsc --noEmit` (два проекта) — чисто; `vitest` — 1 тест; `vite build` — сборка проходит.
- `docker compose config` — оба compose-файла валидны.

**Не проверено.**

`make up` целиком: в среде, где собирался каркас, закрыт доступ к CDN образов
Docker Hub, образы не скачались. Это первое, что нужно проверить руками
на машине разработчика.

**Дальше.** Этап 1 — дерево узлов `org_node`, `app_user`, `audit_log`,

## 2026-08-30 · Этап 1 · Дерево узлов, люди, проверка доступа

**Сделано.**

- `org_node` с материализованным путём `ltree` и GIST-индексом. Свой тип колонки
  `models/types.py` — в SQLAlchemy 2.0.52 встроенного `LTREE` нет, а тянуть
  библиотеку ради тридцати строк не стоит. Кодек для asyncpg — в `core/db.py`.
- `app_user` (10 ролей и 5 статусов из ТЗ) и `audit_log` (только добавление строк).
- Миграция Alembic 0001, включает `ltree` и `pg_trgm`. Проверена в обе стороны.
- `core/access.py` — единственная проверка доступа. Штабной узел получает
  областью видимости путь родителя (ADR 0001).
- `seed`: 27 узлов и 30 человек. На продакшне не запускается — стирает данные.

**Чем проверено.**

- Живая PostgreSQL 16 с `ltree`: 14 тестов зелёные, из них 12 — на права.
- **Мутационная проверка.** Тесты не просто зелёные, они ловят поломки:
  замена `<@` на `@>` — падает 7 тестов; снятие правила «штаб → родитель» —
  падает 2; дубль оператора `<@` в другом файле — падает сторожевой тест.
- `EXPLAIN` подтверждает, что `path <@ ...` идёт по GIST-индексу
  (на 27 строках планировщик выбирает seq scan, поэтому проверял с `enable_seqscan=off`).
- `alembic downgrade base` и обратно `upgrade head` проходят.
- `ruff` чисто, `mypy --strict` — 19 файлов без ошибок.
- Seed на живой базе: 27 узлов (20 УИК, 3 штаба, 2 ТИК, регион, федерация),
  30 пользователей, 10 ролей.

**Не проверено.**

`make test` внутри docker compose — образы Docker Hub в этой среде не скачиваются.
Тесты гонялись по локальной PostgreSQL 16. Стоит прогнать `make test` на своей машине.
