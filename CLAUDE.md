# CLAUDE.md

Правила работы над проектом. Читай этот файл перед каждой задачей и следуй ему без напоминаний.

## Что это за проект

«ШТАБ» — веб-платформа координации наблюдателей на выборах (голосование 18–20 сентября 2026).
Пользователи: наблюдатели на участках (телефон, плохая связь, стресс) и сотрудники штаба (десктоп).
Полное описание — в `docs/ТЗ.md`. При расхождении между этим файлом и ТЗ побеждает ТЗ, но сообщи о расхождении.

**Главный принцип продукта:** система фиксирует факты и ускоряет реакцию. Она не делает выводов о нарушениях, не прогнозирует результаты и не заменяет юриста.

## Стек

- Бэкенд: Python 3.12, FastAPI, SQLAlchemy 2.0 (async), Alembic, Pydantic v2, ARQ (фоновые задачи)
- БД: PostgreSQL 16 с расширениями `ltree`, `pg_trgm`, `postgis`, `vector`
- Redis: pub/sub для WebSocket, кэш, очереди, rate limit
- Хранилище: S3-совместимое, доступ только через presigned URL
- Фронтенд: React 18, TypeScript (strict), Vite, Tailwind, shadcn/ui, TanStack Query, Dexie, Workbox, MapLibre GL, Recharts
- Тесты: pytest + httpx на бэке, Vitest на фронте, Playwright на критические сценарии

Не добавляй новые библиотеки без явного разрешения. Если библиотека кажется необходимой — сначала объясни зачем и предложи альтернативу из уже установленных.

## Структура репозитория


## Команды

```bash

make migrate       # alembic upgrade head

```

После любых изменений в коде запускай `make lint` и `make test`. Не сообщай о завершении задачи, если они падают.

## Инварианты безопасности (нарушение = критический баг)

1. **Права проверяются на сервере.** Клиент только прячет кнопки. Каждый эндпоинт, отдающий чужие данные, обязан фильтровать по поддереву узлов пользователя.
2. **Доступ = поддерево.** Один способ проверки на всю систему: `org_node.path <@ user_scope_path`. Не изобретай второй.
3. **Никто не может повысить себе роль или сменить себе узел.** Создавать пользователей можно только с ролью строго ниже своей и только внутри своего поддерева.
4. **Самостоятельной регистрации нет.** Учётные записи создаёт координатор или администратор, либо они выдаются по одноразовому коду приглашения с зашитой ролью и узлом.
5. **Персональные данные не попадают в логи.** Телефоны маскируются (`+7999***4455`), пароли и токены не логируются никогда.
6. **Фото списков избирателей запрещены.** При категории «проблемы со списками» показывай предупреждение перед открытием камеры.
7. **Все действия штабных ролей пишутся в `audit_log`** — смена ролей, удаление сообщений, рассылки, изменение статуса инцидента.
8. **Идемпотентность обязательна** для всех клиентских POST: `client_uuid` с уникальным индексом. Клиент офлайн отправит одно и то же несколько раз.

## Правила бэкенда

- Слои: `router` (валидация и права) → `service` (логика) → `repository/model` (данные). Логика в роутерах запрещена.
- Все запросы к БД асинхронные. Никаких синхронных вызовов в обработчиках.
- Времена: в БД `timestamptz` в UTC, на клиент отдаём UTC, форматируем в часовом поясе узла.
- Телефон нормализуется в `+7XXXXXXXXXX` в одном месте — `core/phone.py`.
- Ошибки: единый формат `{"error": {"code": "...", "message": "...", "details": {...}}}`. `message` — человеческий текст по-русски, его показывают пользователю.
- Миграции только через Alembic. Ручные правки схемы запрещены.
- Внешние сервисы (LLM, SMS, геокодер, S3) — за интерфейсами в `services/providers/`, с заглушкой для тестов и локальной разработки.

## Правила фронтенда

- Мобильный экран — основной. Проверяй вёрстку на ширине 360 px в первую очередь.
- Целевая область нажатия не меньше 44×44 px. Основные действия — большие кнопки внизу экрана, в зоне большого пальца.
- Любое действие пользователя работает офлайн: пишем в Dexie, показываем статус «ожидает отправки», синхронизируем фоном. Экран «нет соединения» показывать запрещено.
- На главном экране всегда виден счётчик неотправленных событий.
- Оптимистичный UI: сообщение и инцидент появляются мгновенно, с пометкой статуса.
- Никакого `localStorage` для данных — только Dexie. В `localStorage` допустимы лишь флаги интерфейса.
- Фото сжимаются до 1600 px по длинной стороне перед отправкой.
- Тексты интерфейса — по-русски, спокойные и короткие. Никаких «Ошибка 500» — пиши «Не удалось отправить, попробуем ещё раз автоматически».
- Тон формулировок: «зафиксируйте», «сообщите», «уточните». Не «требуйте», не «нарушение подтверждено».

## Код

- Комментарии и сообщения коммитов — по-русски. Имена переменных, функций и таблиц — по-английски.
- Доменные термины не переводим: `uik`, `tik`, `node`, `incident`, `checkin`, `seal`, `protocol`.
- Функции короткие. Если больше 50 строк — разбивай.
- Никаких «на будущее»: не пиши код, который сейчас не используется.
- TODO запрещены. Либо делаем, либо выносим в задачу и говоришь об этом явно.

## Как работать над задачей

1. Сначала план: какие файлы затронешь, какие сущности добавишь, что может сломаться. **Дождись подтверждения перед тем, как писать код**, если задача больше одного файла.
2. Маленькими шагами. Один осмысленный кусок — один коммит.
3. После изменений: `make lint`, `make test`, при необходимости — руками проверь сценарий.
4. В конце коротко: что сделано, что не сделано, что проверить руками.
5. Если требование в ТЗ неполное или противоречит себе — **спроси, не додумывай**. Особенно в правах доступа и в юридических формулировках.
6. Если задача выглядит как «сделай всё сразу» — предложи разбить и начни с первого куска.

## Чего делать нельзя

- Менять модель прав доступа без явной задачи.
- Добавлять аналитику, трекеры, внешние скрипты, шрифты с внешних CDN.
- Отправлять любые данные во внешние сервисы, кроме явно согласованных (LLM-провайдер, SMS-шлюз, геокодер, S3).
- Генерировать юридические формулировки «из головы» в коде или в промптах ИИ-помощника. Правовой текст берётся из базы знаний и шаблонов, утверждённых юристом.
- Писать сообщения интерфейса, которые подталкивают пользователя к конфликту с избирательной комиссией.
- Коммитить секреты. Всё через `.env`, в репозитории только `.env.example`.

## Definition of Done

Задача считается сделанной, если: код проходит lint и типы; есть тест на основной сценарий и на проверку прав; работает на ширине 360 px; работает офлайн (если это клиентское действие); нет ПДн в логах; в ответе описано, что проверить руками.
